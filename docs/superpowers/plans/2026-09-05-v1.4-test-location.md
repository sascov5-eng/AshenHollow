# Ashen Hollow v1.4 Test Location Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved v1.4 continuous developer test location with explicit mechanic hints, hazards, checkpoints, moving platforms, placeholder enemies, interactions, secrets, validated traversal geometry, and the device-proven v1.3 camera unchanged.

**Architecture:** Keep `GameScene` as orchestration only. Add focused Swift units for test-session state, layout, tutorial hints, hazards/respawn, moving platforms, enemies, and interactions. Geometry is data-driven and validated against `PlayerMovementTuning`; CI runs logic/contract tests before compiling and packaging the IPA.

**Tech Stack:** Swift, SpriteKit, UIKit, shell/Python CI checks, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-05-v1.4-test-location-design.md`

## Global Constraints

- Target release is `CFBundleShortVersionString = 1.4`.
- Keep `CFBundleIdentifier = app.ashenhollow.prototype` and `CFBundleVersion = 2`.
- Landscape Left + Landscape Right only.
- Preserve all nine Little Axion animation PNG resources.
- Preserve the device-approved v1.3 camera constants and behavior.
- Top label: `v1.4 • PERFECTED TEST LOCATION`.
- All required mechanics have explicit developer hints.
- Main-route geometry must be validated against real player movement values, not eyeballed.
- New v1.4 systems must not be implemented as additional ad-hoc build-time string replacements.
