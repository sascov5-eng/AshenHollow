# Ashen Hollow v1.6 Trials Design

## Goal
Turn the current developer test scene into a cohesive iOS demo shell centered on compact timed challenge rooms, while fixing the interaction/combat/readability defects observed in v1.5.

## Release identity
- `CFBundleShortVersionString = 1.6`
- `CFBundleVersion = 2`
- `CFBundleIdentifier = app.ashenhollow.prototype`
- landscape left/right only
- visible build label: `v1.6 • ИСПЫТАНИЯ • БОЙ + UI`
- keep camera zoom 1.75 and Little Axion visual size 480×480 at y = -8

## Demo shell
- Main menu with: `ИГРАТЬ`, `НАСТРОЙКИ`, `ОБ ИГРЕ`.
- Trial selection screen.
- Pause overlay with: continue, restart room, return to menu.
- Settings: music volume, effects volume, vibration toggle. No graphics settings.
- No ads, analytics, accounts, online services, cloud saves, purchases, or telemetry.
- Best trial results and settings are stored locally only.

## Trial loop
- Select a room.
- Start timer when control becomes active.
- Complete the room by reaching its finish marker.
- Show result screen with elapsed time, damage taken, enemies defeated, and rank.
- Ranks are A/B/C/D. Rank thresholds are deterministic per room.
- Result screen offers retry and return to trial selection.
- Death/restart resets the current attempt timer and attempt stats.

## Initial room set
Use the existing large test location as source material but expose it as compact trial segments so large new levels are not required.

1. `ПЕРВЫЕ ШАГИ` — movement/jump/spikes/moving platform.
2. `ОХОТА` — ground/flying enemies and combat feedback.
3. `МЕХАНИЗМ` — lever, door, shortcut interaction.
4. `РЫВОК` — wall jump, dash, long jumps and pit.
5. `СМЕШАННЫЙ БОЙ` — mixed combat + platforming.
6. `ФИНАЛЬНОЕ ИСПЫТАНИЕ` — long mixed segment ending at the existing test exit.

Each trial is constrained to a compact x-range and has its own start/finish. Existing world assets may be reused; inaccessible areas outside the active trial are blocked.

## HUD
- Keep on-screen movement/action controls.
- Button backgrounds are semi-transparent, approximately 50–60% opacity.
- Text and outlines remain readable.
- Reduce HUD footprint so it blocks less gameplay.
- Buttons: `ПРЫЖОК`, `АТАКА`, `РЫВОК`, `ЛЕЧЕНИЕ`, `ДЕЙСТВИЕ`.
- Tutorial highlight temporarily increases target-button opacity and shows a bright outline/pulse/arrow.
- Status copy is Russian.

## Interaction fixes
- `ДЕЙСТВИЕ` is the only input for levers/checkpoints.
- Lever interaction radius must be forgiving enough to work reliably on device.
- Lever visibly changes state when activated.
- Linked door immediately opens with an animated movement, not only alpha fading.
- Door has a readable frame/body instead of a thin vertical placeholder.
- Door/lever state persists across death until full trial restart.
- Breakable wall remains attack-driven.

## Combat feedback
- Ground enemy HP: 3.
- Flying enemy HP: 3.
- Aggressive enemy HP: 5.
- Visible HP bar above enemies.
- A successful player melee hit gives 34 LIGHT.
- Enemies receive knockback away from the player on successful melee hits.
- Enemy AI pauses briefly during hit stun.
- Add short hit-stop/impact emphasis, flash and small particles on accepted hits.
- Enemy contact still knocks the player back and deals 1 HP.

## Healing / Focus
There is no dedicated heal sprite sheet in the current Little Axion pack, so healing uses effects layered over the player.

- Hold/start focus for ~1 second.
- Player movement stops during focus.
- Visible light particles/orbit/ring build around the player.
- On completion: brighter pulse and +1 HP.
- Damage, attack, dash, death, or interruption cancels focus.
- Interrupted focus consumes no LIGHT.

## Moving platforms
- Player inherits horizontal and vertical platform delta while standing on a moving platform.
- Walking and jumping remain possible while riding.
- Carry stops immediately after detaching.
- No visible slipping/jitter.

## Visual readability
- Keep Pixel Cave art.
- Improve composition and reduce obvious repeated technical rectangles where existing art can represent the object.
- Doors, levers, checkpoints, moving platforms, hazards and exit must read as distinct gameplay objects.
- Tutorial/world captions stay Russian and must not obscure the main play area.

## Privacy scope
The build does not collect or transmit personal data. Settings and best results remain in local `UserDefaults` only. A simple `ОБ ИГРЕ` screen states this behavior for the demo.

## Acceptance criteria
A player can launch the app, enter the main menu, select a trial, understand the controls, complete the timed room, receive an A/B/C/D rank, retry, pause, change audio/vibration settings, and return to menu. Lever→door interaction, enemy knockback, focus healing feedback, moving-platform carry, Russian UI and v1.6 metadata must all work in the same IPA.
